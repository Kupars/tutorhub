# 小木学长 · 天津家教看板（TutorHub）

无需注册的家教需求看板，适用于老师浏览正在招募的家教单、按地点和时薪筛选排序，并将感兴趣的家教需求加入「选单清单」，复制到微信联系小木同学。管理员可以登录隐藏的后台继续管理家教单。

## 老师如何使用

1. 浏览、搜索家教单。顶部提供「综合推荐（时薪＋路程）」「路程最近」「课时费最高」「最新发布」，默认使用综合排序；填写出发地可以重新估算通勤时长。
2. 点击「筛选条件」展开年级、科目、学生性别、区域、上课时间、最低时薪等组合筛选。
3. 点击卡片上的「+ 加入选单」，下方固定操作条展示已选数量。清单只保存在当前浏览器，不要求老师登录。
4. 点击「查看清单 · 一键复制」，复制标准九字段家教单及编号，再打开微信发送给「小木同学」咨询。复制不会自动发送，也不意味着成功接单。

原老师账号、注册、简历、投递/自动投递、投递审核均已从看板移除，服务端相关接口返回下线提示。历史账号、简历和投递数据保留在 KV 中，**不会自动删除**。

## 管理员后台

- 顶部「管理」入口需管理员邮箱密码，普通老师无需账号。
- 按九字段新增/编辑/下架家教单，保留原编号；支持多科拆分/合并、问询模板复制。
- 支持粘贴微信聊天由智谱等模型整理，草稿核对后发布；支持从飞书导出的 CSV/TSV 批量导入。
- 默认 #2992 续编；缺失成绩显示待补充，不编造学生信息。
- 使用 Cloudflare Pages Functions 和绑定名为 `TUTOR_KV` 的 KV Namespace 持久化订单；云端删除后不会恢复示例数据。

### Cloudflare Pages 部署

使用 GitHub `main` 分支部署到 Pages，静态资源根目录为 `.`，无需构建命令。Cloudflare Pages 项目应绑定：

- KV Namespace：变量名 `TUTOR_KV`
- 管理员鉴权：`ADMIN_EMAIL`、非空 `ADMIN_PASSWORD`、非空 `AUTH_SECRET`（不强制字符长度，仍建议分别使用高强度密码及随机签名密钥）
- AI 模型：可直接在「管理 → AI 模型管理」添加 OpenAI 兼容的 HTTPS 中转站、API Key 与多个模型 ID；`OPENAI_API_KEY`、`OPENAI_BASE_URL`、`OPENAI_MODEL` 仍可作为回退配置。
- 可选：`AMAP_KEY`，提升地址解析精度。无此密钥时，骑行/公交时间是粗略估算值，**不等于地图实际路线时间**。

不要把 API Key 或管理员密码写到前端代码里。旧项目的内置管理员演示凭据只用于本地测试；线上务必配置强密码，避免后台被他人访问。

当前生产接口使用 Cloudflare KV；`supabase/schema.sql` 是历史预留方案，并非运行所必需。

## 2026-11 管理后台：AI 诊断、登记老师与未匹配提醒

- **AI 录单**：通过实际模型接口解析微信零散信息；AI 无法调用时使用保守规则提取，始终输出九字段草稿，管理员确认后才发布。未给出的年级、分数、学生性别、地址不会凭空补充；草稿显示需核实项目。
- **后台 AI 模型管理（推荐）**：管理工作台 →「AI 模型管理」，添加不同中转站的名称、HTTPS API Base URL（例如 `https://relay.yourdomain.com/v1`）、API Key 和多行模型 ID；支持编辑、删除、一键选择模型与测试连通性。模型设置保存在服务端 Cloudflare KV，API Key 使用由 `AUTH_SECRET` 派生的 AES-GCM 密钥加密，浏览器只得到是否配置了密钥，不得到原文或密文。管理员登录和 KV 是必要前提。修改 `AUTH_SECRET` 后须重填已加密的 API Key，且弱 `AUTH_SECRET` 会显著削弱加密安全性。
- **Cloudflare 默认模型回退**：未选择任何自定义中转站或主动切回 Cloudflare 默认配置时，沿用 `OPENAI_API_KEY`、`OPENAI_BASE_URL`、`OPENAI_MODEL`；亦支持原有 `GEMINI_API_KEY` 配置。**密钥绝不能上传 GitHub 或写入前端代码。**
- **AI 修改功能的边界**：只能理解并预览修改公告、主题、指定订单的时薪和状态；必须经管理员确认才执行。不能通过这个输入框直接重写网页代码、修改后台权限或删除订单。
- **编号**：默认从 `#2991` 以后递增，综合已有订单和后端保存的最高编号，关闭或删除单子不会将已发出的编号重新回收。管理员原本明确指定的历史编号不自动篡改。
- **老师匹配记录**：后台订单行点「登记老师」，可录入姓名、可选联系方式及备注，并选择是否一并关闭公开展示。私人匹配记录保存在独立 Cloudflare KV 键 `teacher_assignments`，只有管理员通过 `admin_data` 能查看；公开 API、地图和老师端不输出姓名或联系方式。
- **未匹配提醒**：管理员进入后台时自动提示真实发布日期超过 10 天仍公开招募的单子。历史飞书单的统一导入日期不等于发布时间，因此标注为日期待核实，不谎报逾期。提醒目前是**后台内提醒**，不是关闭浏览器后仍可推送的微信/短信通知。需要后台无人值守推送，须另配可信通知通道和定时调度。
- **推荐老师**：只从管理员已经登记的历史接单记录中，按公开授课区域、公开小区/地标和补习科目进行匹配；不获取老师实时位置、不假设老师住址，不提供老师自助注册。推荐仅供管理员自行联系确认，不等于自动派单。

### 私人数据安全要求

使用老师匹配记录前，Cloudflare 必须同时配置非空 `ADMIN_PASSWORD` 和 `AUTH_SECRET`，不再检查最小长度；缺少任一个时私人记录保存仍会被拒绝。管理员应妥善保管账号与密钥，并只收集完成派单所必需的信息。若当前站点仍使用示例密码，应先更换。


## 2026-11-23 AI 专项升级：仅外部 API、连续对话、智能拆合单

- **内置自然语言解析器已删除**：AI 整理、修改草稿、修改已发布订单／网站设置均通过 Cloudflare Pages Functions 的 `/api/ai` 访问所配置的外部模型。API 故障时会明确报错，不会偷偷使用规则引擎冒充 AI 输出；不影响普通老师浏览看板。
- **格式 Skill**：`shared/tutoring-order-formatter.js` 是每次 AI 调用都会发送的结构化指令，使用 220 条已公开历史单中抽取的 7 条不同情况作为 few-shot 文风样例。它不是对模型的永久训练；换 API/模型后仍复用这套规范。
- **多单处理**：不同学生、不同家庭、明确拆分的科目分别形成草稿；一师带多科不自动拆单；没有明确分工的“2位老师”保留老师人数并提示待核实。模型返回的完整草稿、分组说明和问题都会先在后台展示。
- **手动拆／合**：每张草稿有独立科目选择框。管理员可勾选部分科目“拆分所选科目”，也可从多张草稿勾选科目“合并所选科目”；未选中科目保留。不同年级、学生性别、公开地址的草稿不能直接合并，管理员必须确认同一学生。
- **AI 连续对话**：整理后使用「继续对话修改草稿」，后端会收到最近对话和当前全部草稿，模型返回完整修订版；所有草稿可手动编辑，只有管理员点击确认发布才写入数据库。
- **编号保护**：原文明确写的单号保留，没写时由网站按 `order_sequence` 最高编号分配；拆分主单使用子编号。发布前检查草稿重复编号及与已发布单号冲突。
- **AI 修改网站／订单**：管理员可以连续聊天规划修改首页标题、副标题、公告、网站主题、指定家教单的时薪、科目、上课时间、补课地址、要求与上下架状态等。模型仅生成受白名单约束的计划，浏览器显示每个修改项，管理员明确确认后才执行。
- **能力限制**：普通网页代码、CSS/JS、数据库结构、新功能开发无法通过当前后台聊天框直接改 GitHub；应使用代码审查及 GitHub 更新，不能冒充“已修改代码”。
- **密钥和隐私**：`OPENAI_API_KEY` 仅存 Cloudflare Secret。粘贴的家长微信需求会发送给所配置的第三方 API，请仅发送业务必需的公开信息，不要包含学生姓名、电话、详细门牌和其他敏感个人数据。历史 few-shot 只采用已经公开展示的授课地点摘要。
- **连通性诊断**：「AI 模型管理」可测试任意已保存的模型；「AI 修改网站与订单」页也可测试当前使用的模型。请求会真实调用第三方 API，可能产生费用。不要向 GitHub 提交 API Key。

## 老师储备池 + 投递管理 SOP（2026-11-23）

管理员后台新增「老师档案库与定向推荐」，不再把“登记投递”与“已成功接单”等同。

1. **老师独立储备池**：不需要已有家教单，管理员可先粘贴简历、上传 JPG/PNG/WebP 截图或 TXT/Markdown 文本，点击 AI 提取姓名、学校、明确标注的老师性别、可教科目和教师身份；结果写入**可编辑草稿字段**，管理员核对后才保存。原简历文件不存储在 KV。PDF/DOCX 暂不直接解析，请复制文本或导出截图。
2. **补充可教科目和意向区域**：`canTeach` 是老师明确会教的科目，`preferredDistricts` 是老师主动表达的授课区域；以前投递过某区的订单只代表曾经关注该区，不能代替住址、位置或明确授课意愿。
3. **个人信息安全**：联系方式是独立可选人工字段；AI 不自动填写手机号、微信等。管理员可以填写代理名称（档案级或某一次投递级）。老师档案和投递关系存储于独立 KV 键 `teacher_profiles`、`teacher_applications`，只从管理员接口返回，公开看板 / 地图不会暴露。
4. **一单多位投递**：点击每条家教单的「登记投递」，从储备池关联一位老师并记录进展（已投递、待联系、沟通中、试课中、已接单、未录用）。重复操作可以记录不同老师，也可以编辑当前老师进展；如果老师未入库，点击「还没有档案？先录入老师」，保存档案后自动关联当前单。**投递和进展不会自动修改订单状态**，上下架仍由管理员操作。
5. **接单能力状态**：每位老师可标「可接单 / 已接满 / 暂不接单 / 待确认」。只有**明确可接单**才出现在新单推荐。科目能力先筛选，一名老师带多科时必须覆盖全部学科；教师性别优先被用于加权，硬性「仅限」必须满足。地区偏好、历史投递公开地点和历史接单只作为解释性排序证据，不代表老师现住址或实时可用时间。
6. **新单发布触发推荐**：后台手工发布或 AI 草稿正式发布之后立即弹出每张单的老师候选列表，按明确可带学科、区、历史投递和性别倾向排序。当前是后台即时推荐，不会自动微信私聊老师或自动派单。
7. **一组来源需求多个子单**：在 AI 草稿中选择多条来源确认相同的订单，点「将选中草稿编为同一主单号」，分配 `#3001-1`、`#3001-2` 等；每条仍保留各自学生、科目和上课条件。仅同一个代理转发了不同家庭的单不能直接编组。已发布历史编号不自动批量修改。
8. **旧资料不丢**：之前 `teacher_assignments` 中的老师记录仍保留，可从新的「历史已接单老师记录」中手动预填为老师档案，但默认“待确认”，防止误判其仍能接新单。

安全提示：简历文本会在请求前尽量屏蔽手机号、邮箱和微信字段；**照片可能包含无法自动遮盖的敏感内容**，建议管理员上传前先裁掉证件号、电话、微信和个人住址。所选择的 AI 服务商将接收提交的简历内容；仅在适当授权下处理这些资料。

验证方式：`npm test`，含 `tests/teacher-pool.test.mjs` 中的无单入库、一单三位投递、不可接单筛除、性别/学科匹配、公开数据隔离、简历结构化与子单编号测试。


## 2026-11-23 多选筛选与模块化后台

老师端「科目」「年级」「区域」「方式」「学生性别」「老师性别」「上课时间」都可点击展开复选框，支持同类多选（OR）和跨类叠加（AND）。例如：科目同时选数学、物理，区域同时选南开、津南，会展示两个区域内任一科目的家教单。每类支持全选和清空；已选条件显示在搜索栏下方，点击标签可移除；设置写入原本的本地筛选记忆，并兼容旧版单选字符串数据。

管理员后台改为六个独立功能视图：家教单管理、AI 智能录单、手动录单、老师档案与匹配、AI 修改网站与订单、其他兼职。进入后台先显示工作台概览，点击模块卡片才显示该功能。模块内可返回工作台或通过顶部导航切换；从订单编辑/核对地址自动跳手动录单，从按科目拆单跳 AI 草稿，从登记投递跳老师档案模块。未进入老师档案页时不预加载重模块，避免拖慢后台首页。

回归测试见 `tests/multi-filter-and-admin.test.mjs`。
